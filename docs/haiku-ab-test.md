# Phase 8G — claude-haiku-4-5 A/B 操作说明

不改代码，纯手动操作。目的：评估把 DJ 决策模型从 `claude-sonnet-5` 切到
`claude-haiku-4-5` 能否进一步压缩 `dj_decision_ms`，以及歌单质量是否可接受。

## 背景

Phase 8F 测量确认：`dj_decision_ms`（Anthropic API 调用本身）是决策总耗时的主要
瓶颈，稳定在 10-18 秒，且发生在歌曲搜索/校验之前——8F 的搜索侧优化（早停 + 降
级链预算）无法压缩这部分。换更小的模型是目前唯一可能进一步压缩这段耗时的杠杆，
但会有内容质量风险，所以先做 A/B 实测，不直接切换。

## 前置确认（已在代码里验证，无需操作）

`src/modules/ai.js` 的 `EFFORT_CAPABLE_MODEL_RE` 白名单**不包含** `haiku-4-5`，
所以切到 haiku 后 `output_config.effort` 参数会被自动跳过，不会因为 haiku 不支
持该参数而报 400。这是白名单机制本来的设计（不支持的模型静默降级，而不是报
错），已确认生效，不需要改代码。

## 操作步骤

1. 打开 `/admin` 后台 → AI Settings。
2. 把 model 从 `claude-sonnet-5` 改成 `claude-haiku-4-5`，保存。
3. 用真实账号连续发 3 轮不同类型的请求（建议：一轮中文流行、一轮粤语硬约束、
   一轮点名歌手如"来点周杰伦"），每轮记录：
   - `logs/app.log` 里的 `dj_decision_ms`（可以 `grep dj_decision_ms logs/app.log | tail -3`）
   - `anthropic_call_ms` 那行的 `out_tok`（输出 token 数，供和 sonnet 基线对比）
4. 同时人工检查每轮歌单质量，重点看这几项（对应 Phase 8A-8E 已建立的正确性标准）：
   - **语言纯度**：如果本轮是语言硬约束（如"净係要粵語歌"），7 首是否真的都
     是该语言演唱、`lang` 字段标注是否可信（可以挑 1-2 首自己核实一下，参考
     Phase 8D/8E 遇到过的错标案例）
   - **歌手多样性**：是否覆盖至少 3 位不同歌手，还是明显收窄成一两个大路歌手
   - **say 文采**：换模型后 DJ 人设、语气是否还立得住，是否变得干巴巴或客服
     腔（对照 `src/modules/claude.js` 里的 few-shot 范例语气）
   - **防幻觉**：有没有出现明显编造或张冠李戴的歌名/歌手组合
5. 把 model 切回 `claude-sonnet-5`，保存，确认后续请求恢复正常。

## 怎么判断要不要换

- 如果 `dj_decision_ms` 明显下降（例如从 13-18s 降到 5-8s）且上面 4 项质量检查
  都过关，值得认真考虑长期切换或做每用户可选。
- 如果耗时下降但质量明显滑坡（语言纯度/多样性/文采任一项肉眼可见变差），说明
  这笔延迟换质量的交易不划算，维持 sonnet。
- 这是主观判断，没有自动化脚本产出结论——本文档只负责把对比步骤和该看哪几个
  指标讲清楚，结论由实际测试的人决定。
